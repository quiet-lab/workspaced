# workspaced

Демон workspace для сессии Hyprland (Wayland, CachyOS): держит модель столов
и workspace, расставляет окна по шаблонам, запускает и находит приложения,
пишет и восстанавливает сессии. Демон однопоточный, общается с Hyprland через
Lua-API по unix-сокетам композитора и сам предоставляет unix-сокет для
команд клиента и панели.

Подробные требования к поведению — в спецификациях OpenSpec репозитория
dotfiles: `~/.local/share/chezmoi/openspec/specs/ws-config`, `ws-daemon`,
`ws-sessions`. Формат и место конфига — `~/.config/workspaced/config.toml`
(источник под chezmoi: `dot_config/workspaced/config.toml`).

## Сборка и установка

```bash
cargo build --release
```

Исполняемый файл собирается в `target/release/workspaced`; на него ведёт ссылка
`~/.local/bin/workspaced`, через которую демон и клиентские команды вызываются
из остальной сессии. Демон запускается юнитом пользовательского systemd
`workspaced.service` (источник под chezmoi:
`dot_config/systemd/user/workspaced.service`).

```bash
cargo test
```

Сервер и клиент — один и тот же исполняемый файл, подкоманда
выбирает роль:

- `daemon` — запустить демон (сервер).
- `check` — проверить конфиг и вывести сводку.
- `keys` — напечатать привязки: код Lua для конфига Hyprland (`--lua`),
  таблицу (`--list`) или перечень по группам в JSON для окна подсказки
  клавиш панели (`--json`: у каждой цепочки подпись вида «Shift+Super+/»,
  описание, действие и источник). Описание и группу записи `[[binds]]`
  задают необязательные поля `desc` и `group`, описания зарезервированных
  сочетаний — таблица `keys.reserved_desc`; без них описание и группа
  выводятся из действия.
- `half` — поставить активное окно в половину рабочей области.
- `maximize` — развернуть активное окно на рабочую область с отступами;
  повторно — вернуть прежние положение и размер.
- `place` — поставить активное окно в позицию рабочей области (половина
  ширины и высоты в углах и по центру рядов, `center` — на всю высоту,
  `full` — вся область).
- `status` — напечатать состояние демона.
- `raise` — поднять workspace на столе.
- `key` — клавиша приложения: все привязки клавиш приложений вызывают
  `workspaced key '<цепочка>'`, а приложение и workspace демон выбирает при
  нажатии по активному workspace текущего стола (`key_route`, четыре шага).
  Сначала клавиша ведёт к окну там, где оно сейчас есть: если приложение
  с такой собственной клавишей или приложение, которому её назначил ключом
  любой workspace, входит в активный workspace (описано в нём или его окно
  несёт тег состава), — цикл по его окнам в активном. Иначе запущенный
  workspace откликается — поднять его; приложение описано только
  в запущенных workspace, переопределивших его клавишу, — перетащить его
  окна в активный; иначе открыть приложение в активном. Цепочка, на которую
  никто не отзывается, — строка в журнале без действия.
- `app` — собственная клавиша приложения по имени: те же шаги, где
  workspace откликается, если описывает приложение и не переопределяет его
  клавишу; поэтому приложение, чей запущенный workspace назначил ему другую
  клавишу, перетаскивается в активный workspace. Несколько имён — кандидаты
  (так вызывали привязки прежних версий). С `--pull` окна приложения
  перетаскиваются в активный workspace стола и остаются в прежних.
- `key --new` и `app <имя> --new` — новый экземпляр приложения: приложение
  и workspace выбираются теми же шагами, что без ключа, а вместо цикла
  по окнам запускается новый экземпляр — на месте приложения в активном
  workspace (в режиме `swap` приложение сначала занимает главное место),
  в поднятом workspace приложения, в активном workspace стола по правилам
  открытия либо на месте по умолчанию вне workspace. Каждый такой запуск
  заводит свою запись ожидания, даже если прежний запуск ещё не дал окна;
  окно достаётся самой ранней подходящей записи. В записи `[[binds]]` —
  действие `{ app = "<имя>", new = true }`.
- Шаг цикла по экземплярам приложения: выбрать следующий, а за последним
  вернуться к прежнему окну. Что значит «выбрать», задаёт режим приложения
  в workspace: `swap` — обмен мест с главным приложением, `stack` — подъём
  окна наверх без переноса. Режим — поле `mode` записи приложения, без
  него — режим workspace, в том числе у приложения, место которого задано
  `rect` (записью файла или записью сессии). В режиме `swap` клавиша
  неглавного приложения всегда ставит его на главное место: выбирается
  активное окно, если оно экземпляр приложения, иначе первый экземпляр.
  Раскладку и память окон режим не задаёт — см. «Раскладка workspace».
- `detach` — убрать активное окно из активного workspace стола: окно,
  входящее в другие workspace, уходит к ним, последнее вхождение закрывает
  окно.
- `next` — поднять следующий workspace из списка текущего стола.
- `save-workspace` — записать раскладку активного workspace в конфиг.
- `remove` — убрать workspace из списка стола (окна уходят к другому своему
  активному workspace или на `special:pool`).
- `sessions` — открыть в панели окно выбора сессии.
- `session` — сессии (подкоманды `save`, `load`, `list`).
- `help` — напечатать эту справку или справку по подкоманде.

## Цепочки с выходом

Раздел `[sticky.<имя>]` описывает режим клавиатуры: сочетание входа `enter`
открывает подкарту Hyprland корневого состояния `ws-sticky:<имя>`, и она
остаётся открытой, пока не нажата клавиша с `exit = true`, Escape (с любого
уровня) или Backspace в корне; Backspace во вложенном состоянии возвращает
к родителю. Состояния — вложенные таблицы `states`, у каждого `title`,
`keys` и необязательное `apps`. Клавиша состояния — имя одной клавиши без
модификаторов; значение — переход `{ state = "<дочернее>" }` либо действие
`action`, `exec`, `dispatch`, `lua` с необязательными `exit` и `desc`.
`apps = "raise"` добавляет в состояние буквы всех клавиш приложений
Super+буква с действием `workspaced key '<цепочка>'`, `apps = "spawn"` —
с `workspaced key --new '<цепочка>'`; запись без действия дополняет такую
клавишу (`e = { exit = true }`), запись с действием заменяет её.

В коде Lua (`keys --lua`) у каждого состояния своя подкарта
`ws-sticky:<имя>/<состояние>/…`: клавиши с `ignore_mods = true` (Super после
входа можно не отпускать), BackSpace, Escape и последней `catchall`
с `hl.dsp.no_op()`, которая поглощает остальные нажатия. Действие
`catchall` пустое намеренно: композитор выполняет его и вместе с совпавшей
привязкой. Код заканчивается проверкой текущей подкарты: подкарта `ws:…`
(одноразовые цепочки прежних версий) или `ws-sticky:…`, которой в новом
коде нет, закрывается, иначе после
перечитывания конфига сессия осталась бы без привязок. Демон состояния
режима не хранит. `keys --list` показывает режим путями (`SUPER+S r v`),
`keys --json` — группой «Цепочки с выходом» и разделом `sticky` для
индикатора панели.

Многозвенные цепочки из любого раздела конфига (`[keys]`, `chain`
у workspace и приложений, `[[binds]]`) — тоже режимы: все цепочки с одним
первым сочетанием образуют режим `ws-sticky:<первое сочетание>`
(`ws-sticky:SUPER+TAB`), общие промежуточные звенья — вложенные состояния
(`ws-sticky:SUPER+W/3`), а последние звенья — клавиши выхода: действие
выполняется, и режим закрывается. Посторонние нажатия поглощает `catchall`,
BackSpace и Escape работают так же, как в разделах `[sticky.*]`. Звено без
модификаторов привязывается с `ignore_mods`, звено с модификаторами
(`CTRL+SUPER+w`) — точно, поэтому его нажимают, не отпуская модификаторов
сочетания входа. Звенья Escape и BackSpace и пара звеньев одной клавиши, где
у одного модификаторов нет, отклоняются проверкой. `keys --list` помечает
последнее звено флагом `exit`, `keys --json` даёт режим в разделе `sticky`
с подписью префикса («Super+Tab») и описаниями клавиш из подсказки.

## Раскладка workspace

Раскладка workspace в памяти демона (`State::cells`, `State::moved`,
`State::main`) назначает каждому приложению раздела место: исходное —
ячейку шаблона или `rect` записи — и, если окно сдвигали или растягивали,
изменённый прямоугольник. Прямоугольник места — изменённый, а без него
исходный; по нему ставятся новые окна, запускаемые приложения и окна без
запомненного прямоугольника. Главное приложение хранится явно: при первом
обращении это поле `main` раздела, без него — приложение ячейки `main`
шаблона.

- Событий о перемещении окна Hyprland не присылает, поэтому раскладка
  снимается с экрана в момент действия (`absorb_plan`, `absorb_into`):
  перед циклом клавиши приложения, поднятием и вытеснением workspace,
  переносом на стол, уходом окна со стола своего workspace, удалением
  workspace из списка стола и командами сохранения. Берётся первое окно
  записи на столе, где workspace активен, не скрытое и не полноэкранное;
  прямоугольник, равный исходному месту, изменённого места не даёт.
  Опроса и таймеров нет.
- Обмен мест (`swap_places`) передаёт места целиком — исходное вместе
  с изменённым прямоугольником — и делает главным вызванное приложение:
  сдвинутое окно отдаёт свой прямоугольник прежнему главному приложению.
- Прямоугольник окна запоминается для каждого его workspace в обоих режимах
  (`State::geom`): пришедшее на стол окно встаёт туда, где его оставили,
  а окно, уже стоящее на столе, поднятие не двигает.
- Закрытие или отделение последнего окна приложения снимает его изменённое
  место (`drop_moved`, владелец места — адрес окна): следующее окно встанет
  на исходное. `arrange` снимает изменённые места всех приложений
  workspace, не отменяя обмена.
- В конфиг раскладка попадает только командой `save-workspace`: место,
  совпадающее с ячейкой шаблона, пишется её именем, иначе `rect`, главное
  приложение — полем `main`. Перечитывание изменённого раздела собирает
  раскладку заново и сразу ставит окна активного workspace по ней.

`workspaced status --json` показывает раскладку в полях `cells`, `main`
и `moved` на момент последнего действия.

## Сессии и снимок

Сессии лежат в `~/.local/state/workspaced/sessions/<имя>.toml`; `default`
пишет только команда сохранения (`workspaced save-session`, в сессии —
Ctrl+Super+S дважды), именованные — `workspaced session save <имя>`.
Кроме столов, раскладок workspace (исходные места `cells`, главное
приложение `main`, изменённые места `moved`) и дополнительных приложений
сессии снимок хранит список `[[windows]]`. Раскладку снимок получает только
по команде сохранения; прямоугольник записи дополнительного приложения —
место, с которым оно принято, — команда не переписывает, сдвинутое окно
даёт изменённое место. Окно с тегом экземпляра записывается так:

```toml
[[windows]]
app = "neovide"
instance = 2                  # номер из тега app:neovide#2
workspaces = ["work"]         # теги состава ws:<имя>, по алфавиту
desktop = "1"                 # «1»…«8», «pool» или «hidden»
cmd = ["neovide", "notes.md"] # только у экземпляра с собственным процессом, кроме первого
cwd = "/home/mne/notes"

[windows.rect]                # где окно стоит сейчас
x = 3055
y = 10
w = 1920
h = 2140

[windows.rects.surf]          # прямоугольник, в котором окно оставлено в surf
x = 1700
y = 60
w = 1920
h = 2140
```

Командную строку и каталог получает только экземпляр, у процесса которого
нет других окон и который не первый у своего приложения; первый экземпляр
запускается командой приложения из конфига, а окна процесса, который держит
и другие окна (второе окно браузера), открывает сам процесс. Свободное окно
без тега записывается со столом, командной строкой, каталогом
и прямоугольником. Признак нового формата — поле `instance`: снимок без него
читается и восстанавливается по прежнему правилу «одно окно на приложение»,
а прежняя версия демона новые поля пропускает. Прямоугольники `rects` пишутся
для всех workspace окна; снимок без полей `main` и `moved` читается,
раскладка тогда собирается из конфига.

Восстановление ведётся по плану в памяти (`State::restore`, записи
`RestoreEntry`):

- запись, для которой есть живое окно с тем же тегом (перезапуск демона),
  исполнена сразу: ничего не запускается, состав окна не меняется, из записи
  берутся только прямоугольники `rects`;
- экземпляр с командной строкой запускается при поднятии первого из своих
  workspace, до захвата окон; первый экземпляр — командой приложения;
  запись без workspace — после поднятия workspace активного стола;
- появившееся окно сопоставляется с записью сначала по pid запущенного
  процесса, затем по приложению в порядке номеров, получает номер записи
  (если он свободен), теги состава и место по правилу размещения;
- окон без командной строки, кроме первого экземпляра, демон ждёт, только
  если сам запустил приложение при восстановлении; ожидание снимают клавиша
  приложения, команда сохранения и загрузка сессии, сроков у него нет.
  Вторые окна браузера возвращаются, только если браузер восстанавливает
  свои окна сам (настройка «При запуске: продолжить с того же места»);
- сохранение переносит в новый снимок записи workspace, ещё не поднятых
  после старта;
- загрузка именованной сессии сверяет живые окна приложения с записями
  по порядку номеров: лишние окна получают штатный запрос закрытия,
  недостающие восстанавливаются, как при старте.

План и приложения, запущенные при восстановлении, показывает
`workspaced status --json` (поля `restore` и `restore_apps`). Требования —
спецификация `ws-sessions`, проектные решения — изменение `session-instances`
в репозитории dotfiles.

## Устройство кода

- `main.rs` — точка входа: разбор командной строки (`clap`), сброс SIGPIPE
  в состояние по умолчанию (клиент печатает в канал, например `| head`;
  без сброса обрыв канала завершался бы паникой, а так процесс просто
  прекращает работу), подкоманда `check` со сводкой по конфигу.
- `config.rs` — разбор `~/.config/workspaced/config.toml`: проценты и
  пиксели, три слоя окружения с подстановкой `~` и `$ИМЯ`, проверки, записи
  `[[binds]]`. Запись приложения в таблице `apps` workspace (`WsApp`) —
  имя ячейки строкой, `{ rect = … }` или таблица с `cell` либо `rect`
  и необязательными `chain` (клавиша приложения в этом workspace) и `mode`
  (режим его клавиши); помощники `ws_entry`, `app_key`, `overrides_key`,
  `app_mode`, `responds` отвечают, какая запись описывает приложение, какой
  у него ключ и режим и чем workspace откликается на цепочку.
- `keys.rs` — сочетания и цепочки: одна привязка `workspaced key` на
  цепочку со всеми откликами (собственные клавиши и ключи записей
  workspace), две записи одного workspace с одним ключом, конфликты,
  список `reserved`, генерация Lua, цепочки с выходом (`sticky_nodes`:
  наследование клавиш приложений, проверки, подкарты `ws-sticky:…`
  с `catchall`, закрытие устаревшей подкарты), режимы многозвенных цепочек
  (`auto_nodes`: дерево цепочек по первому сочетанию), таблица
  для `keys --list`, копия кода в `~/.local/state/workspaced/keys.lua`.
- `keys_help.rs` — перечень для `keys --json`: подписи сочетаний, группы
  по назначению и описания, серия `range` одной строкой («Super+1…8»),
  зарезервированные сочетания в группе «Раскладка», строки цепочек
  с выходом и раздел `sticky` для индикатора.
- `hypr.rs` — сокеты Hyprland: диспетчеры выражениями Lua, несколько шагов
  одной последовательностью `(function() … return … end)()`, мониторы
  с рабочей областью, активное окно.
- `state.rs` — столы, раскладки workspace (исходные и изменённые места,
  главное приложение), посторонние окна, дополнительные приложения сессии,
  незаконченный цикл клавиши и запомненные прямоугольники окон, план
  восстановления из снимка, формат сессии.
- `daemon.rs` — поднятие workspace, цепочка приложения как цикл по
  экземплярам (`cycle_step`, `anchor_window`, `next_app_window`,
  `select_window`), `half`, `place`, `maximize`, запуск с `setsid`
  и сопоставление окна по pid, `/proc/<pid>/exe` и классу, тег экземпляра
  `app:<имя>#<номер>`, состав workspace тегами `ws:<имя>` (`ws_windows`,
  сверка `stale_ws_tags` и `derive_membership`), правило размещения окна
  (`window_home`), раскладка в памяти (`absorb_plan`, `swap_places`,
  `drop_moved`, `keep_layout`, `arrange_layout`), следование окон за столом
  (`follow_plan`), путь клавиши
  приложения (`key_route`, `app_route`) и режим цикла по приложению
  (`cycle_mode`), парковка на `special:pool`, сервер сокета
  `$XDG_RUNTIME_DIR/workspaced/sock` строками JSON с подпиской. Там же
  эффективный конфиг (`merge_extra`): файл плюс дополнительные приложения
  сессии, — и наблюдатель конфига, который
  перечитывает файл по событиям завершённой записи (`write_finished`).
- `session.rs` — снимок текущего состояния (`snapshot`, запись окна
  экземпляром — `instance_record`), запись сессии `default` по команде
  сохранения, именованные сессии, восстановление при старте со сверкой
  (`restore_default`, план восстановления `restore_plan`), ленивое поднятие
  workspace остальных столов, загрузка со сверкой по экземплярам
  (`load`, `load_pairs`). Сопоставление появившегося окна с записью плана
  (`match_restore`), место восстановленного окна (`restore_place`) и запуск
  экземпляров при поднятии workspace (`raise_restore_step`) — в `daemon.rs`.
- `save.rs` — две команды сохранения: `save-session` принимает посторонние
  окна стола в активный workspace как дополнительные приложения сессии
  и снимает с экрана раскладки (конфиг не меняется), `save-workspace`
  записывает раскладку workspace в конфиг (`place_item`: имя ячейки или
  `rect`) через `toml_edit`: таблица `apps` раздела правится на месте — у записи
  меняется только место, `chain`, `mode`, порядок записей и комментарии
  сохраняются, новые записи встают в конец (`set_place`, `write_places`).
- `client.rs` — команды командной строки к работающему демону.

## Что стоит знать до правки

- `j/monitors` отдаёт `reserved` массивом `[left, top, right, bottom]`; при
  работающей панели это `[330, 0, 0, 0]`. В Lua-API форма того же поля
  не документирована, демон читает сокет и полагается на массив.
- Поля окна в Lua-API (`/usr/share/hypr/stubs/hl.meta.lua`, класс
  `HL.Window`): `stable_id` (порядок создания, по нему идёт обход окон
  стола), `focus_history_id`, `mapped`, `address`, `class`, `title`, `tags`,
  `at`, `size`, `floating`, `hidden`, `pid`, `workspace`. Окно пользователя
  выбирается по тегу `app:<имя>#<номер>`, а не по классу; номер различает
  экземпляры приложения, а тег `app:<имя>` без номера остался от прежней
  версии демона и читается как экземпляр. В какие workspace окно входит,
  говорят теги `ws:<имя>`, по одному на workspace; вывода состава
  из описания приложений в конфиге больше нет, кроме выдачи состава окнам
  прежней версии при старте.
- serde: `deny_unknown_fields` действует только на структуру, на вариант
  перечисления его повесить нельзя. Неизвестные ключи отлавливаются
  на структурах разделов конфига (`config.rs`), варианты действия проверяет
  код.
- Новый вид действия: сначала применить конфиг (`chezmoi apply`), затем
  перезапустить юнит. В обратном порядке новый демон получает старый конфиг,
  отвергает его и завершается с ошибкой.
- При собственном старте демон привязки Hyprland не перезагружает, нужен
  `hyprctl reload config-only`; после удачного перечитывания файла демон
  выполняет его сам.
- SIGTERM демон не обрабатывает (в `main.rs` сбрасывается только SIGPIPE):
  снимок `default` пишет только команда сохранения (`save-session`, а также
  `session save` и загрузка именованной сессии), и состояние, изменившееся
  после неё, при остановке демона намеренно теряется — перезапуск
  и перезагрузка возвращают систему к последнему сохранению.
- Запуск приложений: `wezterm-gui start` без `--always-new-process` открывает
  окно в уже работающем wezterm; `/usr/bin/firefox` — сценарий оболочки,
  поэтому исполняемый файл дочернего процесса читается из `/proc`, пока он
  жив; Telegram одноэкземплярный, и его окно принимается по событию выхода
  запущенного процесса — предельного срока ожидания окна нет, ожидание живёт
  до окна (`pending_step` в `daemon.rs` описывает переходы); `kill -SEGV`
  процесс на Rust переживает.
- Таймеров в демоне нет и не должно быть: каждое место, где раньше стояло
  ожидание по времени, реагирует на событие — изменение состояния,
  завершённую запись файла, выход процесса, появление окна. Решение
  и причина — запись `0007-no-timers.md` в репозитории chezmoi
  (`~/.local/share/chezmoi/docs/decisions/0007-no-timers.md`).
- Тесты: `cargo test`.
